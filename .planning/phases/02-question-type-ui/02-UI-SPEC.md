# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope Note

Phase 2 replaces or wraps the existing `QuestionPanel.tsx` with a dispatching component that renders all 5 `TypedListeningQuestion` variants as distinct interactive layouts. The setup card, player, and feedback panel are unchanged. The question card in `app/listening/page.tsx` gains typed question components in place of the current textarea-per-question approach.

**Schema prerequisite:** `GapFillQuestion` in `lib/types.ts` currently has `text` and `acceptedAnswers` but no `sentence` field. The executor must add `sentence: string` (containing a `___` placeholder) to `GapFillQuestion` and update the generation prompt before implementing the gap-fill renderer. This is locked by CONTEXT.md D-05 and D-06.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gap inside chip, dot indicator offset |
| sm | 8px | Gap between chips in icon grid, gap between A/B/Ambos buttons |
| md | 16px | Vertical gap between question rows, input horizontal padding |
| lg | 24px | Section padding within question card |
| xl | 32px | Gap between stacked question type blocks |
| 2xl | 48px | Not used in Phase 2 |
| 3xl | 64px | Not used in Phase 2 |

Exceptions:
- Icon chip touch target: minimum 44px height to meet accessibility touch requirements (may exceed 8-point grid). Width is flexible per icon count.
- Person-attribution button row height: 36px per button (py-2 equivalent — 8px top + 8px bottom + line height).

Source: Inherited from Phase 01 contract; exceptions derived from CONTEXT.md D-01/D-02 and accessibility standards.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (text-sm) | 400 (regular) | 1.5 |
| Label | 10px (text-[10px]) | 600 (semibold) | 1.2 |
| Heading | 18px (text-lg) | 600 (semibold) | 1.2 |

Notes:

- Question text: `text-sm text-zinc-300` — matches existing pattern

- Gap-fill inline input text: `text-sm text-zinc-100` — matches body, seamless with surrounding sentence text
- Section heading "Questions": `text-sm font-semibold text-zinc-300 uppercase tracking-wide` — preserve existing QuestionPanel heading

Source: Observed from `app/listening/page.tsx` and `components/listening/QuestionPanel.tsx`; Phase 01 UI-SPEC.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `oklch(0.145 0 0)` — zinc-950 | Page background (`bg-zinc-950`) |
| Secondary (30%) | `oklch(0.205 0 0)` — zinc-900 via gradient | Card surface, unselected chip backgrounds |
| Accent (10%) | sky-400 / sky-500 (`#38bdf8` / `#0ea5e9`) | Selected state: chip border, glow shadow, dot indicator; MCQ selected radio fill |
| Destructive | Not used in Phase 2 | — |

Accent reserved for:
1. Selected chip in icon-matching grid (border-sky-400/50 + background tint + dot indicator) — exact MarkSelector pattern from Phase 01
2. Selected button in True/False/Not Given three-option row
3. Selected button in person-attribution A/B/Ambos row
4. Selected radio option in MCQ (if using custom radio, the indicator fill)

All unselected interactive elements use `border-white/10` with `hover:border-sky-400/25` — never full accent fill.
Disabled state (during loading): `pointer-events-none opacity-60` — matches MarkSelector pattern.

Source: `app/listening/page.tsx` chip classes; Phase 01 UI-SPEC color contract; CONTEXT.md D-02.

## Component Inventory

### Dispatching component: TypedQuestionPanel

Replaces `QuestionPanel.tsx` as the top-level question renderer.

**Location:** `components/listening/TypedQuestionPanel.tsx`

**Props:**
```ts
interface Props {
  questions: TypedListeningQuestion[]
  answers: Record<string, string>
  onAnswerChange: (id: string, value: string) => void
  disabled?: boolean
}
```

Dispatches to a per-type sub-component based on `question.type`. Wraps each question in a `div` with `space-y-1.5` consistent with existing `QuestionPanel.tsx` row spacing.

### Sub-component: McqQuestion renderer

**Location:** `components/listening/McqRenderer.tsx` (or co-located in TypedQuestionPanel)

**Layout:** Question text above a vertical list of radio-style option buttons. One option per row.

**Option button appearance (unselected):**
```
rounded-xl border border-white/10 bg-gradient-to-br from-zinc-800 via-zinc-900 to-zinc-950
px-4 py-2.5 text-sm text-zinc-200 text-left w-full
hover:border-sky-400/25 hover:text-white transition-all duration-200
```

**Option button appearance (selected):**
```
border-sky-400/50 bg-gradient-to-br from-sky-400/20 via-sky-500/10 to-zinc-950
text-white shadow-[0_8px_20px_-10px_rgba(56,189,248,0.6)]
```

**Option label prefix:** Letter prefix A, B, C, D rendered as `text-[10px] font-semibold uppercase text-zinc-500 mr-2` before option text.

**State:** `useState<string>` local to the renderer; calls `onAnswerChange(question.id, selectedIndex.toString())` on selection.

**Disabled state:** `pointer-events-none opacity-60` on the entire option list.

**Layout:** Question text above a single row of 3 toggle-style buttons.

**Decision (Claude's Discretion — resolved):** 3-button toggle row, same pattern as person-attribution, not radio group. More compact and visually consistent with the A/B/Ambos pattern.

**Button row:** `flex gap-2 mt-2`

**Button appearance (unselected):**
```
rounded-xl border border-white/10 bg-gradient-to-br from-zinc-800 via-zinc-900 to-zinc-950
px-4 py-2 text-xs font-semibold text-zinc-300
hover:border-sky-400/25 hover:text-white transition-all duration-200

**Button appearance (selected):**
```
border-sky-400/50 bg-gradient-to-br from-sky-400/20 via-sky-500/10 to-zinc-950

**Button labels:** "True" / "False" / "Not Given" (full words, not abbreviated — options are few enough).

**State:** `useState<string>` local; calls `onAnswerChange(question.id, value)` where value is `'true' | 'false' | 'not-given'`.

**Disabled state:** `pointer-events-none opacity-60` on the button row.

### Sub-component: GapFill renderer

**Location:** `components/listening/GapFillRenderer.tsx`

**Schema dependency:** Requires `GapFillQuestion.sentence: string` containing `___` as the blank marker. Executor must add this field to `lib/types.ts` and update the generation prompt. See schema prerequisite note at top of this spec.

**Layout:** Sentence rendered inline. The `___` placeholder is split out and replaced with an `<input>` element inline in the text flow.

**Sentence rendering:** Split `question.sentence` on `___`. Render as: `<span>{before}</span><input /><span>{after}</span>` inside a `<p className="text-sm text-zinc-200 leading-relaxed">`.

**Input appearance:**
```
inline-block w-32 border-b-2 border-zinc-600 bg-transparent
text-sm text-zinc-100 text-center outline-none
focus:border-sky-400 transition-colors duration-200
mx-1 px-1
```
No box border — only bottom border to convey "fill in the blank" inline. On focus, border upgrades to sky-400.

**State:** `useState<string>` local; calls `onAnswerChange(question.id, value)` on `onChange`.

**Disabled state:** `disabled` attribute on the input + `opacity-60` on the containing `<p>`.

### Sub-component: IconMatching renderer

**Location:** `components/listening/IconMatchingRenderer.tsx`

**Decision (D-01):** Icon-only chip grid — no text labels. User must identify concept from icon alone.

**Decision (D-02):** Same chip pattern and selected state as MarkSelector. Grid layout, 2–4 icons per row.

**Layout:** Question text above a grid of icon chips.

**Grid:** `grid grid-cols-4 gap-2` for 4 or fewer icons; `grid grid-cols-3 gap-2` if icon count is 3 or fewer. If icon count exceeds 4, use `grid grid-cols-4 gap-2` and wrap.

**Chip appearance (unselected):**
```
relative overflow-hidden rounded-2xl border border-white/10
bg-gradient-to-br from-zinc-800 via-zinc-900 to-zinc-950
flex items-center justify-center
min-h-[44px] aspect-square
hover:border-sky-400/25 transition-all duration-200 active:scale-[0.99]
```

**Chip appearance (selected):**
```
border-sky-400/50 bg-gradient-to-br from-sky-400/20 via-sky-500/10 to-zinc-950
shadow-[0_20px_45px_-30px_rgba(56,189,248,0.95)]
```

**Selected indicator dot:** Absolute positioned `h-2.5 w-2.5 rounded-full` in top-right corner: `bg-sky-300 shadow-[0_0_0_6px_rgba(125,211,252,0.13)]` when selected, `bg-zinc-600` when not. Matches MarkSelector chip dot exactly.

**Icon rendering:** Lucide icon resolved by `question.icons[n].name` (the string icon name). Use a `LucideIcon` dynamic lookup via the `lucide-react` icon map. Icon size: `w-5 h-5` (20px). Color: `text-zinc-300` unselected, `text-white` selected.

**State:** `useState<string>` local storing `selectedIconName`; calls `onAnswerChange(question.id, selectedIconName)` on selection.

**Disabled state:** `pointer-events-none opacity-60` on the grid.

### Modified: app/listening/page.tsx

`answers` state changes from `string[]` to `Record<string, string>` to support per-question-id keying. `QuestionPanel` import replaced with `TypedQuestionPanel`. The `onAnswerChange` handler updates by question `id` rather than array index.

The `script` state type changes from `ListeningScript` to `TypedListeningScript` once the typed generation path is confirmed working. During transition, both types may coexist in state — the executor should consult `lib/types.ts` and the Phase 01 plan summaries for the current state shape.

## Interaction Contract

### Common behaviors across all question types

| State | Behavior |
|-------|----------|
| Initial (no answer selected) | All options unselected; no answer stored |
| User selects an option | That option highlights with sky accent; others deselect immediately (single-select) |
| User changes selection | Previous selection loses highlight; new selection gains it |
| `disabled=true` | `pointer-events-none opacity-60` on the entire question input area |
| Loading | Identical to `disabled=true` — questions visible but not interactive |

### MCQ — specific behaviors

| Interaction | Result |
|-------------|--------|
| Click an option | Option becomes selected; others clear |
| Option label | Letter prefix A/B/C/D rendered in muted zinc-500, then option text |

### True/False/Not Given — specific behaviors

| Interaction | Result |
|-------------|--------|
| Click True, False, or Not Given | That button selected; others clear |
| Re-click selected | No change (stays selected; no deselect toggle) |

### Gap-fill — specific behaviors

| Interaction | Result |
|-------------|--------|
| Click input | Border upgrades from zinc-600 to sky-400 |
| Type text | Value stored via onAnswerChange in real time |
| Input blur | Border returns to zinc-600 |

### Icon-matching — specific behaviors

| Interaction | Result |
|-------------|--------|
| Click icon chip | Chip selected with sky accent border + glow + dot; others clear |
| Icon size | w-5 h-5 (20px) — recognizable but not oversized |
| Icon name fallback | If Lucide icon name not found, render a `HelpCircle` icon instead of crashing |

### Person-attribution — specific behaviors

| Interaction | Result |
|-------------|--------|
| Click A, B, or Ambos | That button selected; others on same row clear |
| Row layout at narrow viewport | Buttons may wrap below statement text — use `flex-wrap` on the row container as fallback |

### Submit button ("Check Answers")

The existing submit button in `app/listening/page.tsx` remains. Its disabled condition changes from `answers.every((a) => !a.trim())` (array) to checking that `Object.values(answers).some(v => v.trim())` (record). The button is enabled as soon as at least one answer is non-empty.

## Accessibility Contract

- All icon chips must have `aria-label={icon.label}` even though no visible label is shown (D-01 is visual-only; screen readers need the label).
- All toggle button groups (TFNG, person-attribution) must have `role="group"` on the container with a visually hidden `aria-label` identifying the question.
- MCQ options rendered as `<button>` elements must have `aria-pressed={selected}`.
- Gap-fill `<input>` must have `aria-label="Fill in the blank"`.
- Disabled state must use both CSS opacity and the `disabled` HTML attribute (not CSS alone).

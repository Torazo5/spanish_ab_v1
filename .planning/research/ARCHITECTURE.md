# Architecture: IB-Authentic Listening Question Types

**Domain:** Multi-type listening question system for Next.js 14 App Router
**Researched:** 2026-03-31
**Overall confidence:** HIGH — analysis based on direct codebase inspection

---

## Executive Summary

The existing listening feature is a thin pipeline: one API route generates a script + 5 uniform open-ended questions, the page holds flat string array answers, and a second route AI-grades all of them. The new milestone replaces this with a heterogeneous question set (5 distinct types), client-side grading for deterministic types, and a transcript-reveal / review-mode learning layer.

The core architectural challenge is the **discriminated union**: every place that currently assumes `ListeningQuestion` (type, API, prompts, components, page state) must be updated to handle a typed union where each variant carries different answer-shape data. Everything else — component splitting, grading routing, review state — follows directly from getting that union right.

## Question 1: TypeScript Discriminated Union

### Recommended shape

```typescript
// lib/types.ts  (replaces existing ListeningQuestion / ListeningScript / AnswerResult)

// --- Question variants ---

export interface McqQuestion {
  id: string
  type: 'mcq'
  text: string
  options: string[]          // 3-4 options, index 0-3
  correctIndex: number       // 0-based, included in API response at generation time
}

export interface TfngQuestion {
  id: string
  type: 'tfng'
  text: string               // the statement to evaluate
  correctAnswer: 'true' | 'false' | 'not_given'
}

export interface GapFillQuestion {
  id: string
  type: 'gap_fill'
  text: string               // "El tren sale a las ___ de la mañana"
  // no correct answer field — AI-graded; LLM sees script + expected answer
}

export interface IconMatchQuestion {
  id: string
  type: 'icon_match'
  text: string               // "¿Qué transporte usa Ana?"
  options: IconOption[]
  correctIconId: string      // must match an option's iconId
}

export interface IconOption {
  iconId: string             // exact Lucide export name, e.g. "Bus", "Plane", "Train"
  label: string              // Spanish label shown below icon
}

export interface PersonAttributionQuestion {
  id: string
  type: 'person_attribution'
  text: string               // the statement to attribute
  personA: string            // name, e.g. "María"
  personB: string            // name, e.g. "Carlos"
  correctAnswer: 'A' | 'B' | 'both'
}

export type ListeningQuestion =
  | McqQuestion
  | TfngQuestion
  | GapFillQuestion
  | IconMatchQuestion
  | PersonAttributionQuestion

// --- Script container ---

export interface ListeningScript {
  script: string
  title: string
  questions: ListeningQuestion[]
}

// --- Answer shapes ---

// Client stores answers in a map keyed by question id.
// The value type depends on question type.
export type McqAnswer          = number                         // option index
export type TfngAnswer         = 'true' | 'false' | 'not_given'
export type GapFillAnswer      = string
export type IconMatchAnswer    = string                         // iconId
export type PersonAnswer       = 'A' | 'B' | 'both'

export type QuestionAnswer =
  | { type: 'mcq';              value: McqAnswer }
  | { type: 'tfng';             value: TfngAnswer }
  | { type: 'gap_fill';         value: GapFillAnswer }
  | { type: 'icon_match';       value: IconMatchAnswer }
  | { type: 'person_attribution'; value: PersonAnswer }

export type AnswerMap = Record<string, QuestionAnswer>

// --- Grading ---

export interface ClientGradedResult {
  questionId: string
  source: 'client'
  correct: boolean
}

export interface AiGradedResult {
  questionId: string
  source: 'ai'
  correct: boolean
  feedback: string
}

export type AnswerResult = ClientGradedResult | AiGradedResult

export interface GradingResponse {
  results: AiGradedResult[]
  totalAiScore: number
  maxAiScore: number
  encouragement: string
}
```

### Why this shape

- `type` as the discriminant lets TypeScript narrow correctly in every switch/if block — no runtime `instanceof` checks.
- Correct answers live **inside** the question object (generated by LLM, returned in API response). This enables client-side grading with no extra state.
- `AnswerMap` (keyed by question id, not array index) is safer than a positional array when question order changes or partial renders occur.
- `GapFillQuestion` intentionally has no `correctAnswer` field — the LLM grader reconstructs expected answers from the script.

## Question 2: generate-script API Response Restructure

### What changes

The route currently returns `{ script, title, questions: ListeningQuestion[] }` where questions have only `{ id, text }`. The new contract must embed correct answers for deterministic types.

**New prompt contract** (to be built in `lib/prompts/listening.ts`):

```
Generate a Spanish listening exercise.
Return ONLY valid JSON with this exact schema:

{
  "script": "...",
  "title": "...",
  "questions": [
    // MCQ example
    { "id": "q1", "type": "mcq", "text": "...", "options": ["a","b","c","d"], "correctIndex": 2 },

    // True/False/Not Given
    { "id": "q2", "type": "tfng", "text": "...", "correctAnswer": "false" },

    // Gap-fill (no correct answer in JSON; AI grades from script)
    { "id": "q3", "type": "gap_fill", "text": "El vuelo sale a las ___ horas." },

    // Icon-matching
    { "id": "q4", "type": "icon_match", "text": "...",
      "options": [
        { "iconId": "Bus",  "label": "autobús" },
        { "iconId": "Plane","label": "avión" },
        { "iconId": "Train","label": "tren" }
      ],
      "correctIconId": "Plane"
    },

    // Person attribution
    { "id": "q5", "type": "person_attribution", "text": "...",
      "personA": "María", "personB": "Carlos", "correctAnswer": "A" }
  ]
}
```

### Route changes

`app/api/listening/generate-script/route.ts` needs:
- `max_tokens` increased from 1000 to ~1800 (richer question objects)
- Same markdown-fence stripping + JSON.parse pattern
- Return type is now `ListeningScript` (new shape) — no structural change to the route handler itself, only the prompt and token budget

### Icon safety constraint

The LLM must only emit Lucide icon names that actually exist. The prompt must include a **closed list** of permitted icon identifiers. Keep it to ~12-15 icons covering the IB topic set (transport, food, weather, activities, family). The icon component on the client performs a dynamic lookup and falls back to a generic icon when unknown — defensive rendering is required.

Permitted icon list (to embed in prompt):
`Bus, Plane, Train, Car, Bike, UtensilsCrossed, Apple, Cloud, Sun, Heart, BookOpen, Music, Baby, Users, Smartphone`

## Question 3: check-answers Route Scope

### Recommendation: send only AI-gradable questions

The route should receive only `gap_fill` (and any open-ended) questions. Client-side grading is already complete before the API call is made.

**New request body:**

```typescript
// POST /api/listening/check-answers
{
  script: string,
  aiQuestions: Array<{ id: string; text: string }>,  // gap_fill questions only
  aiAnswers: Record<string, string>                   // questionId -> answer string
}
```

**Why not send all answers:**
- Sending MCQ/TFNG/icon/person answers to the LLM wastes tokens and introduces inconsistency risk (LLM might disagree with the deterministic correct answer).
- The LLM grader's output is merged with client results in the page, not used as the single source of truth.
- Simpler prompt, lower token usage, more reliable on the free tier.

**Response from route stays similar:**

```typescript
{
  results: AiGradedResult[],
  totalAiScore: number,
  maxAiScore: number,
  encouragement: string
}
```

The page merges AI results with client results to compute a unified `totalScore`.

## Question 4: Client-Side State for Transcript Reveal and Review Mode

### State machine extension

The existing `PageState = 'setup' | 'loaded' | 'answered'` needs two new booleans orthogonal to page phase:

```typescript
type PageState = 'setup' | 'loaded' | 'submitted' | 'review'

// In ListeningPage component state:
const [pageState, setPageState] = useState<PageState>('setup')
const [transcriptVisible, setTranscriptVisible] = useState(false)
const [answers, setAnswers] = useState<AnswerMap>({})
const [clientResults, setClientResults] = useState<ClientGradedResult[]>([])
const [aiResults, setAiResults] = useState<AiGradedResult[]>([])
```

### Transcript reveal

`transcriptVisible` is a simple boolean toggle, available in all states after script loads. The `ListeningPlayer` component receives the `script` text and a `transcriptVisible` prop; it conditionally renders the text block. No new state machine state needed.

### Review mode

`'review'` is a distinct `PageState` entered from `'submitted'` via a "Review with transcript" button. In review mode:
- `transcriptVisible` is forced `true`
- Questions render in an amended state: deterministic questions show correct/incorrect highlighting; gap-fill/open-ended questions unlock the textarea again
- Re-submitting in review mode only re-grades the AI questions (same check-answers route, same request shape)
- A separate `reviewAnswers: AnswerMap` state holds amendments, keeping the original submitted answers unchanged for comparison display

### State transition diagram

```
setup
  └─ [generate] → loaded
       └─ [submit answers] → submitted
            ├─ [new exercise] → setup
            └─ [review with transcript] → review
                  └─ [re-submit] → submitted  (overwrites aiResults only)
                  └─ [new exercise] → setup
```

### Key rule

`transcriptVisible` is **independent** of `PageState`. User can reveal at any time in `loaded`, `submitted`, or `review`. Only the ListeningPlayer receives and renders the prop.

## Question 5: Component Architecture

### Principle: one component per question type, thin QuestionPanel as renderer

Do not modify `QuestionPanel.tsx` to be a monolith with 5 branches. Instead:

```
components/listening/
  ListeningPlayer.tsx           MODIFY  — add transcriptVisible + script reveal panel
  QuestionPanel.tsx             MODIFY  — becomes a map/switch dispatcher only, ~30 lines
  FeedbackPanel.tsx             MODIFY  — accepts merged ClientGraded + AiGraded results
  question-types/
    McqQuestion.tsx             NEW
    TfngQuestion.tsx            NEW
    GapFillQuestion.tsx         NEW
    IconMatchQuestion.tsx       NEW
    PersonAttributionQuestion.tsx  NEW
```

### QuestionPanel (dispatcher)

```typescript
// components/listening/QuestionPanel.tsx
export function QuestionPanel({ questions, answers, onAnswer, disabled, showCorrect }: Props) {
  return (
    <div className="space-y-4">
      {questions.map((q) => {
        const answer = answers[q.id]
        switch (q.type) {
          case 'mcq':
            return <McqQuestion key={q.id} question={q} answer={answer} onAnswer={onAnswer} disabled={disabled} showCorrect={showCorrect} />
          case 'tfng':
            return <TfngQuestion key={q.id} question={q} answer={answer} onAnswer={onAnswer} disabled={disabled} showCorrect={showCorrect} />
          case 'gap_fill':
            return <GapFillQuestion key={q.id} question={q} answer={answer} onAnswer={onAnswer} disabled={disabled} />
          case 'icon_match':
            return <IconMatchQuestion key={q.id} question={q} answer={answer} onAnswer={onAnswer} disabled={disabled} showCorrect={showCorrect} />
          case 'person_attribution':
            return <PersonAttributionQuestion key={q.id} question={q} answer={answer} onAnswer={onAnswer} disabled={disabled} showCorrect={showCorrect} />
        }
      })}
    </div>
  )
}
```

TypeScript will enforce exhaustive handling (no default needed if all union members are covered).

### Per-type component contracts

Each question component receives:

```typescript
interface QuestionTypeProps<Q, A> {
  question: Q
  answer: A | undefined        // undefined = unanswered
  onAnswer: (id: string, answer: QuestionAnswer) => void
  disabled?: boolean
  showCorrect?: boolean        // true in submitted/review states
}
```

`showCorrect` drives highlight rendering (green/red borders, checkmark icons). The component receives enough data from `question` to determine correctness without an external results array — the correct answer is in the question itself.

### McqQuestion

Renders a button grid (not radio inputs, for styling control). On click calls `onAnswer(q.id, { type: 'mcq', value: index })`. When `showCorrect`, applies `border-green-600` to `correctIndex`, `border-red-600` to the wrong chosen index.

### TfngQuestion

Three-button row: "True", "False", "Not Given" (English labels acceptable in practice tool). Same highlight pattern.

### GapFillQuestion

A single `<Textarea>` (existing primitive). No `showCorrect` styling — AI feedback is shown in `FeedbackPanel` instead.

### IconMatchQuestion

Icon grid using Lucide dynamic lookup:

```typescript
import * as LucideIcons from 'lucide-react'

function getIcon(iconId: string) {
  const Icon = (LucideIcons as Record<string, React.ComponentType<{ className?: string }>>)[iconId]
  return Icon ?? LucideIcons.HelpCircle  // safe fallback
}
```

Each option renders as a card: icon above, Spanish label below. Selected card gets ring highlight. `showCorrect` state applies green/red border to correct/wrong selections.

### PersonAttributionQuestion

Three-button row: `personA name`, `personB name`, "Ambos" (hardcoded string). Layout same as TfngQuestion. `showCorrect` highlights the correct button.

### FeedbackPanel changes

Accept combined results:

```typescript
interface Props {
  questions: ListeningQuestion[]
  clientResults: ClientGradedResult[]
  aiResults: AiGradedResult[]
  totalScore: number
  maxScore: number
  encouragement: string
}
```

Render per-question: for client-graded questions, show simple correct/incorrect badge. For AI-graded, show the feedback string. The `questionId` key links results back to questions for display.

### ListeningPlayer changes

Add `script: string` (already present) and `transcriptVisible: boolean` prop. When true, render the script text in a scrollable `<pre>`-style block below the player controls, styled as a subtle reveal panel (zinc-900 bg, monospace-ish text, not a modal).

## Client Grading Logic (where it lives)

Client grading happens in `app/listening/page.tsx`, not in a hook. The logic is:

```typescript
function gradeClientSide(questions: ListeningQuestion[], answers: AnswerMap): ClientGradedResult[] {
  return questions
    .filter(q => q.type !== 'gap_fill')
    .map(q => {
      const answer = answers[q.id]
      let correct = false
      switch (q.type) {
        case 'mcq':
          correct = answer?.type === 'mcq' && answer.value === q.correctIndex; break
        case 'tfng':
          correct = answer?.type === 'tfng' && answer.value === q.correctAnswer; break
        case 'icon_match':
          correct = answer?.type === 'icon_match' && answer.value === q.correctIconId; break
        case 'person_attribution':
          correct = answer?.type === 'person_attribution' && answer.value === q.correctAnswer; break
      }
      return { questionId: q.id, source: 'client' as const, correct }
    })
}
```

On submit: run `gradeClientSide`, then send AI request for gap_fill questions only (if any), then merge results and set `pageState = 'submitted'`.

## Pitfalls to Watch

**Icon name casing:** Lucide exports use PascalCase (`Bus`, not `bus`). The LLM must emit PascalCase exactly. The prompt must state this explicitly and the permitted list must use PascalCase. The client must have a fallback for any unrecognised name.

**Token budget:** A 5-question multi-type JSON response with icon arrays can approach 600-700 output tokens. Current `max_tokens: 1000` is marginal. Use 1800 to be safe.

**Gap-fill blank marker:** The prompt must specify `___` (three underscores) as the blank marker so it renders consistently in the component. The GapFillQuestion component can render the sentence with the blank styled distinctly (e.g. underline span) if the text is split on `___`.

**LLM correctIndex off-by-one:** Prompts should specify "0-based index" explicitly. Validate in the route: if `correctIndex >= options.length`, reject or clamp.

**AnswerMap vs array:** The page uses an object keyed by `q.id`, not a positional array. The `QuestionPanel` `onAnswer` callback must accept `(id: string, answer: QuestionAnswer)`, not `(index: number, value: string)`. The page no longer initialises with `new Array(n).fill('')`.

**Review mode answer separation:** Keep original submitted answers (`submittedAnswers`) and review amendments (`reviewAnswers`) as separate state variables. FeedbackPanel can compare them to show what changed.
